# サブエージェント委譲ポリシー

スキル群で「サブエージェント」と呼ぶ委譲先は、以下の優先順位で実行する。

## 実行方式の優先順位

1. **実行環境がサブエージェントをサポートする場合**（例: Claude Code の Task 系、Anthropic Agent SDK のマルチエージェント機能など）
   → 各作業を**別々のサブエージェント**として起動する。
2. **実行環境がプロセスレベルのエージェント実行をサポートする場合**（OSプロセス単位でエージェントを起動できる場合）
   → 各作業を**独立したOSプロセス**として起動する。
3. **上記いずれも利用できない場合のみ**
   → 親エージェント内で各作業を順に実行する（シミュレート）。

サブエージェントもプロセスランナーも利用できる環境で、親エージェント内に全作業を閉じ込めて逐次シミュレートしてはいけない。

「サブエージェントが許可されている場合は」のような条件分岐は不要。サブエージェントまたはプロセスが使えるなら必ずそちらを使う。

## モデル選択

委譲先には作業の性質に応じたモデルを割り当てる。全委譲先を同じモデルで起動しない。

区分は2つ。

**探索区分** — 事実の収集に徹する作業。ファイル探査、grep での列挙、インベントリ作成、既存資料の読み取りと要約、機械的な整形など。判断を伴わず、出力が「見つかったものの一覧」に収まるもの。軽量モデルを割り当てる。

**判断区分** — 判断・生成を伴う作業。設計、実装、レビュー、違反の認定、分類、優先度づけ、ドキュメントの更新など。誤りが成果物に残るもの。メインエージェントと同じモデルを使う。

迷ったら判断区分にする。探索区分の誤りは見落としで済むが、判断区分の誤りは下流に伝播する。

実行環境ごとの割り当て:

| 実行環境 | 探索区分 | 判断区分 |
| --- | --- | --- |
| Claude Code | サブエージェント起動時に `model: sonnet` を指定 | モデルを指定しない（メインを継承） |
| OpenCode | `-m opencode-go/deepseek-v4-flash` を指定 | モデルを指定しない（メインを継承） |
| Agent SDK | 軽量モデル（Sonnet 系）を指定 | メインと同じモデル |
| その他 | 環境で利用できる軽量モデル | 既定モデル |

OpenCode で `opencode/...-free`（OpenCode Zen 無料枠）を委譲先に指定してはいけない。context が 200K に制限され、サブスク契約中でもサブエージェントが無料枠のレート制限で弾かれる既知の不具合がある。

軽量モデルを選べない環境では、区分ラベルを無視して既定モデルで起動してよい。区分ラベルは委譲の要否を変えない。

各スキルは委譲先に **（探索区分）** または **（判断区分）** のラベルだけを付ける。モデル名は書かない。

## 画像を扱う委譲

スクリーンショットやデザインカンプの判定を伴う委譲は、区分に関わらず **vision 対応モデルを明示的に指定する**。メインが text-only モデルで動いている環境では、継承すると画像を読めないまま「問題なし」と返ってくる。

| 実行環境 | 指定するモデル |
| --- | --- |
| Claude Code | 指定しない（メインを継承。Opus / Sonnet はいずれも vision 対応） |
| OpenCode | `-m opencode-go/kimi-k3` を指定 |

委譲先には「画像を読めなかった場合は判定せず、その旨を報告して止まる」ことを明示する。読めていないことに気づかないまま進むのが最悪の失敗。

## 並列実行の原則

- 独立した作業は**必ず並列で**起動する。直列だと遅すぎる。
- 依存関係がある場合のみ順序を守る（依存先を先に完了させる）。

## 委譲時のコンテキスト

- 各委譲先には**独立したコンテキスト**を渡す。前の結果を前提にしない（ゼロベースで実行させる）。
- 委譲先には必ず**プロジェクトルートの CLAUDE.md を最初に読むよう指示する** — コマンド・規約・構成の情報源として。
- 複数の委譲先に同じプロンプトを渡すと似た結論に収束しやすい。視点を分ける場合は視点ごとに明確に指示を変える。

## 失敗時のフォールバック

- いずれかの委譲先が失敗・タイムアウトした場合は、成功した結果だけで柔軟に進める。
- 全部失敗した場合のみ親エージェントでやり直す。
