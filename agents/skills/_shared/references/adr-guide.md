# ADR（Architecture Decision Records）ガイド

設計中に非自明な判断を下したら `spec/adr/NNN-title.md` に記録する。「なぜそうしたか」が残っていれば、実装者が迷わず、将来の変更時にも意図を追える。

## 記載項目

- **ステータス**: 承認済み
- **コンテキスト**: なぜこの決定が必要になったか
- **決定**: 何を決めたか
- **検討した代替案**: 各案と不採用の理由
- **影響**: この決定がもたらす結果・トレードオフ

## ADR を書くべき判断の例

- ドメイン境界の切り方
- 集約の設計（何をひとつの集約にまとめるか）
- 複数のモデリング手法のうちどれを採用したか
- パフォーマンスや一貫性のトレードオフ
- ページ構成・ナビゲーション方針など、体験設計上の非自明な選択
