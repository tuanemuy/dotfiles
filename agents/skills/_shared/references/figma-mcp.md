# Figma MCP

Figma のデザインを読むスキル（figma-import・spec-implement・design-flow）が共有する、公式の Figma MCP の事実と読み方の規則。応答の保存先 `{figma-dir}` と、参照コードをどのスタックに書き換えるかは、呼び出し側のスキルが決める。

## ノードの指定

`fileKey` と `nodeId` は URL から取る（`figma.com/design/{fileKey}/...?node-id=1-2` の nodeId は `1:2`）。

## ツール

- `create_session`: `fileKey` と作業の短い説明を渡し、`sessionId` を受け取る。`use_figma` などファイルを扱うツールを呼ぶ前に 1 回呼び、以後の呼び出しに同じ `sessionId` を渡す
- `use_figma`: Plugin API のスクリプトを実行する。次はこれで取る
  - ページの一覧（`figma.root.children`）と、ページ直下のフレームの id・名前・サイズ
  - ローカルの Variables の全定義（`figma.variables.getLocalVariableCollectionsAsync()`）。コレクション・モード・エイリアスを含む
  - テキストスタイルとエフェクトスタイルの一覧
  - コンポーネントセットとバリアントの一覧。ホバー・フォーカス・無効などの状態は、フレームではなくバリアントで描かれていることが多い
  - フレーム配下のノードを走査して集めた値（塗り・線・角丸・余白・gap・フォント・影と、それぞれが Variables に結び付いているか）
- `use_figma` を呼ぶ前に、公式プラグインの `/figma-use` を読み込む。1 回のスクリプトで切り替えるページは 1 つまでとし、複数のページは並列の呼び出しに分ける
- `get_metadata`: ノードの id・名前・サイズの木を返す。`nodeId` を省いて返るページの一覧は全ページを含まないので、ページの一覧には使わない
- `get_design_context`: フレームの React + Tailwind の参照コード、使われているテキストスタイル、スクリーンショットを返す。値は `var(--{Variables 名}, {値})` の形で入る
  - 大きいフレームは中身の薄い応答になるので、子ノードを引き直す
  - 呼ぶ前に、公式プラグインの `/figma-design-to-code` を読み込む（プラグインが必須にしている）。プラグインの指示は次のように読み替える
    - スクリーンショットを見た目の目標にする指示は、フレーム幅での並べ比べで満たす。一致の根拠は値の照合とする
    - スタックとコンポーネントの再利用は、呼び出し側のスキルの定めに従う
- `get_screenshot`: ノードの PNG の URL を返す（URL は短時間で切れる）。`maxDimension` をフレームの長辺以上にして等倍で取り、すぐに保存する
- `get_variable_defs`: そのノードの配下で使われている Variables とテキストスタイルを、解決済みの値で返す。ローカルに定義の無い値（ライブラリから使っている Variables など）を補うのに使う
- テキストスタイルの `letterSpacing` は % で返り、参照コードは px で書かれる
- 画像とアイコン: `get_design_context` の応答にある URL は 7 日で切れる。その場で保存する。応答に無い画像は `download_assets` で取る

## 呼び出し回数

上限がある。Professional 以上のプランの Full / Dev シートは 1 日 200〜600 回・1 分 10〜20 回、View / Collab シートは月 6 回まで。

- 着手時に `whoami` でプランとシートを確かめ、必要な回数を見積もる。`whoami` は上限の数を返さない。プランから上限が決まらないときは、範囲の下限（1 日 200 回・1 分 10 回）を上限とみなす。回数は Figma MCP の全呼び出しの合計で、委譲先と検証役が引く分も含める
- 1 分に投げる呼び出しは、1 分の上限の半分までにする。並列で委譲するときは、委譲先ごとに 1 分に使ってよい回数を割り当てて渡し、合計を半分に収める
- 1 日の上限に届いたら、Figma を読まずに進められる作業だけを進め、残りは翌日に回す

## 応答の保存

応答は `{figma-dir}` に保存し、同じ呼び出しを 2 度しない。保存するのは呼び出した本人で、同じ作業の担当どうしで共有する。

- ノードへの呼び出しは `{nodeId}.md`（nodeId の `:` は `-` にする）に、ツールごとの節に分けて参照コード・テキストスタイル・Variables の値を書き出す
- フレームのスクリーンショットは `{nodeId}.png`
- `use_figma` の結果は、取ったものの名前で置く（`pages.md`・`variables.md`・`styles.md`・`components.md`・`values-{ページ名}.md`）
- `{figma-dir}` は `git rev-parse --git-path info/exclude` が示すファイルに足してコミットに入れない

## 読み方の規則

- Figma のファイルを書き換えない。`use_figma` で実行するのは読み取りだけのスクリプトに限る
- Figma のデザインを良くしようとしない。Figma と食い違う「改善」は、レビューや検証で勧められても入れない
- Figma から読めない値を推測で埋めない
- Figma との一致は、読んだ値との照合で示す。スクリーンショットが似ていることを一致の根拠にしない。スクリーンショットは、要素の抜け・並びの違い・画像の欠けを探すのに使う
- Figma MCP を使えないときは、スクリーンショットからの再現に切り替えず止まる
