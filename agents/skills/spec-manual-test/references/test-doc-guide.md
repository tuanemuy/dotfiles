# 手順書の形式

`spec/manual-tests/` の形式を定める。何を書き、何を書かないかは SKILL.md の完了の定義が定める。

## 一覧

出力先: `spec/manual-tests/index.md`

```markdown
# マニュアルテスト一覧

## 概要

| 項目 | 値 |
|---|---|
| 対象プロジェクト | {プロジェクト名} |
| spec バージョン | {spec の最終更新のコミットハッシュ} |

## 手順書

| カテゴリー | ファイル | テストケース数 | 正常系 | 異常系 | spec 未決 |
|---|---|---|---|---|---|
| {カテゴリー名} | [{category}.md](./{category}.md) | {数} | {数} | {数} | {数} |
| **合計** | | **{数}** | **{数}** | **{数}** | **{数}** |

## 実行記録

| 実行日 | 実行者 | 環境 | 結果 | 備考 |
|---|---|---|---|---|
| | | | {PASS 数}/{件数} PASS | |
```

## 手順書

出力先: `spec/manual-tests/{category}.md`。カテゴリーは `spec/scenario/{category}.md` と揃える。

### ヘッダーと前提条件

```markdown
# {カテゴリー名} テスト

対応シナリオ: `spec/scenario/{category}.md`

## 前提条件

### 環境
- {起動するサーバーと URL}

### テストデータ
- {利用者・レコードと、その値}

### 事前準備
1. {準備手順}
```

- 環境には、manual-test がサーバーの起動コマンドとポートを読み取れるように書く
- テストデータは、各テストケースが単独で実行できるだけ用意する。テストケースどうしで同じデータを書き換えるときは、テストケースごとに別のデータを用意する

### テストケース

正常系を先に、異常系を後に並べる。

```markdown
## TC-{連番}: {テスト名}

**種別**: 正常系 / 異常系
**対応フロー**: {台帳の番号}
**目的**: {このテストケースで確かめること}

| # | 操作 | 期待結果 |
|---|---|---|
| 1 | {開始する画面を開く} | {期待結果} |
| 2 | {操作} | {期待結果} |
```

- 1 つのテストケースは 1 つのフローを確かめる
- 最初の操作で、開始する画面を開く
- 操作は画面・要素・入力値を具体的に書く。「情報を入力する」ではなく「名前欄に `テスト太郎` と入力する」
- 期待結果は画面で判定できる状態を書く。「正しく表示される」ではなく「一覧の先頭に `テスト太郎` が表示される」
- 異常系の期待結果には、scenario が定める利用者の次の操作ができることまで書く
- 画面名・操作名は `spec/pages/` の語を使う

### フロー対応表

手順書の末尾に置く。

```markdown
## フロー対応表

| フロー | 対応TC | spec 未決の問い |
|---|---|---|
| {台帳の番号}: {フローの要約} | TC-{連番} | |
| {台帳の番号}: {フローの要約} | spec 未決 | {決まっていない問い} |
```
