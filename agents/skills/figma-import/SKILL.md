# Figma Import

Figma のデザインから、デザイントークン・デザイン方針・画面と Figma のフレームの対応表を `spec/design/` に取り込む。画面の HTML は作らない。

- トークンと方針の正本は `spec/design/` とする
- 画面の見た目の正本は、対応表に載ったフレームとする。実装（`../spec-implement/SKILL.md`）がフレームを直接読んで写す
- Figma の Variables・スタイル・フレームの構成を変えたら、このスキルを再実行して取り込み直す

段取り（フレームの読み方・委譲の切り方・確かめ方）は画面数と Figma の作りに合わせて自分で決める。このスキルが定めるのは、入力・成果物・完了の定義・独立した読み・不変条件・予算。

着手時に、読んだ Figma の規模感と採る段取りを一言宣言する。

## 入力

- Figma の URL。ファイル・ページ・フレームのどれでもよい
- `spec/pages/index.md`: 対応表に載せる画面の一覧と、各画面の目的・機能。無ければ `../spec/SKILL.md` でページ設計を先に行うよう提案して止まる
- `spec/scenario/`: あれば、画面の用途を読むのに使う

`spec/design/index.md` の「取り込み元」が同じ Figma を指していれば、状態で分ける。

- 取り込み中: 前回の続きとして再開する。成果物と完了の定義を照らし、成り立っていない条件から進める
- 完了: 取り込み直しとして、Figma の今の値で成果物を書き換える。「正本の分担」が無い「取り込み元」は、画面の HTML まで作っていた形式の取り込みで、これも取り込み直しにする

## 成果物

| ファイル | 形式 | 値の出どころ |
| --- | --- | --- |
| `spec/design/tokens.md` | `../design-flow/references/phase2-tokens.md` の Step 1 | Figma |
| `spec/design/index.md` | 同 Step 2 と、下の「取り込み元」「補う規則」 | Figma から読み取れる方針。読み取れない項目は補う |

- 形式と Figma の値が食い違うときは、値は Figma に従う。色は Figma の値を OKLCH に変換し、HEX を併記する。OKLCH は、HEX に戻したときに Figma の HEX と一致する桁まで残す
- CSS カスタムプロパティの名前は、`get_design_context` の参照コードが `var(--…)` に書く Variables の名前（`/` や空白を `-` にした形）をそのまま使う（`--ink`・`--space-48` など）。design-flow の命名例には合わせない。Variables の無い値だけ design-flow の命名規則で名付ける
- Variables にテーマのモード（Light / Dark など）があれば、フレームが使っているモードだけを取り込み、他のモードは `index.md` のスコープ外の項に書く
- 書体は Figma の書体を指定する。Web フォントとして読み込めない書体は、フォールバックを決めて `tokens.md` に書き、「補ったもの」に載せる
- ブレークポイントは design-flow の標準値を使う
- design-flow の「デザイン原則」（様式の選定）は適用しない。`index.md` のデザイン様式の項には、Figma から読み取れる様式を書く

完了したら、「取り込み元」の状態を「完了」にして残存課題を書き、`spec/index.md` に `spec/design/` の成果物を追記する。

### 取り込み元

`spec/design/index.md` に次を書く。着手時に Figma の URL と状態を書き、対応表は作りながら埋める。止まった後の再開はここから始まる。

- 状態: 取り込み中 / 完了。着手時に「取り込み中」と書き、完了の定義が成り立つまで変えない。design-flow は「取り込み中」の間、画面を作らない
- Figma のファイル URL と取り込んだ日
- 正本の分担: トークンと方針は `spec/design/`、画面の見た目は対応表のフレーム
- 画面と Figma の対応表（画面名・デスクトップのフレーム・モバイルのフレーム・状態のフレームかバリアント）。フレームは名前と nodeId で書く。Figma に無い画面とビューポートは「Figma に無い」と書く
- 残存課題: 独立した読みの申し送り（下の「反例の重さ」）。無ければ「なし」

### 補う規則

Figma に無いものを実装で作るときの規則を、`index.md` の `## 補う規則` の節に次の 4 項目で書く。他のスキルはこの節を名前で参照する。実装はこの規則と対応表だけを見て、Figma に無いものを作れる必要がある。

- トークンに無い値の扱い: 余白・角丸・フォントサイズは、差が 2px 以下の近いトークンに寄せる。それ以外のトークンの対象は寄せない（取り込みの時点で `tokens.md` にある）。幅と高さはフレームで読んだ値をそのまま使う
- 片方のビューポートしか無い画面の、もう片方の作り方。デスクトップとモバイルを切り替えるブレークポイントは Step 2 のレスポンシブ戦略に書き、ここから参照する
- Figma に無い画面の作り方: どの画面を手本にし、共通要素（ヘッダー・ナビゲーションなど）をどこから取るか
- Figma に無い状態の作り方: ホバー・フォーカス・アクティブ・無効・エラーと、空・読み込み中の見せ方

### index.md の書き方

- 規則は 1 か所に 1 回だけ書き、画面や状態ごとの例外を並べない
- トークンが示すこと（寸法・書式・色）を文章で繰り返さない
- 作業の記録と、取り込みの経緯を書かない

### 作業の記録

次は `{figma-dir}`（下の「環境の事実」）に置き、`spec/design/` には書かない。取り込みの間だけ使う記録で、読み手に渡し、要約を完了報告に載せ、完了したら `{figma-dir}` ごと消す。`spec/design/` から `{figma-dir}` を参照しない。

- 補ったもの: Figma から読み取れず補った方針の項目と、書体のフォールバック
- 照合の根拠: 完了の定義の各条件の「根拠」

## 完了の定義

次の 3 つが成り立ち、それぞれを根拠で示せること。成り立つとは、止める反例（下の「反例の重さ」）が無いこと。申し送りは残っていてよい。

### 1. 対応表が揃っている

- `spec/pages/index.md` の全画面に行がある
- 行に載ったフレームは Figma に実在し、名前と幅が行の画面・ビューポートに合う
- Figma にある画面のフレームは、デスクトップとモバイルの両方とも行に載っている
- 同じ画面の状態を描いたフレーム（入力済み・エラー・メニューを開いた状態・絞り込み後など）とバリアントは、別の画面にせず、その画面の行に載っている
- Figma にあって `spec/pages/index.md` に無いフレームは行にせず、完了報告に挙げる

根拠: 対応表と、ページ・フレームの一覧（`use_figma` の結果）

### 2. トークンが Figma を写している

トークンにする値（以下「トークンの対象」）は、色・フォントサイズ・行の高さ・字間・ウェイト・余白・角丸・影・線の太さ。幅と高さは対象にしない。

- ローカルの Variables（取り込むモード）・テキストスタイル・エフェクトスタイルは、すべて `tokens.md` にあり、値が Figma と一致する。色は HEX で照らす
- 対応表のフレームで使われているトークンの対象の値は、どれも `tokens.md` にあるか、「補う規則」で寄せる先のトークンがある
- 2 つ以上のフレームに現れる値と、余白・角丸・フォントサイズ以外のトークンの対象は、寄せずに `tokens.md` にある
- ビューポートで変わる値（見出しのサイズ・余白）は `tokens.md` にある。Variables にビューポートのモード（Desktop / Mobile など）があれば、モードごとの値をそのまま使う

根拠: フレームを走査して集めた値の一覧と、`tokens.md` との照合結果

### 3. 方針が実装に足りる

- `index.md` に Step 2 の項目と、`## 補う規則` の節の 4 項目がある。Step 2 のレスポンシブ戦略に、デスクトップとモバイルを切り替えるブレークポイントがある
- Figma から読み取れない項目は「補ったもの」に載っている
- デザイン様式・レイアウトの原則・インタラクションの方針は、対応表のフレームから読み取れるものと食い違わない

根拠: `index.md` の該当節と、「補ったもの」

### 反例の重さ

反例は、止める反例と申し送りに分ける。

止める反例は、食い違う相手（Figma の保存済みの値・`spec/pages/index.md` の行・トークンの規則・不変条件）を引用して示せるもの。直すまで完了にしない。

- `spec/pages/index.md` の画面が対応表に無い。行のフレームが実在しないか、別の画面・ビューポートを指している
- Variables・スタイルが `tokens.md` に無いか、値が Figma と食い違う
- 走査した値に、`tokens.md` にも寄せる先にも無いものがある
- 「補う規則」の項目が無い
- 不変条件に反している

申し送りは、止める反例に当たらないもの。直さず、「取り込み元」の残存課題に置く。

- 補った方針の書きぶりや細部
- 記録の読み方で反例かどうかが変わるもの
- 3 条件の外の指摘

## 独立した読み

完了と判断する前に、新しいコンテキストのサブエージェント 1 体に読ませる（委譲方式と待ち方は `../_shared/references/subagent-policy.md`）。

- Figma の URL、`spec/pages/index.md`、`spec/design/`、`{figma-dir}`（応答と作業の記録）、完了の定義の 3 条件と反例の重さ（転記）を渡す
- 読み手は保存済みの Figma の応答を `tokens.md`・対応表・`index.md` と照らし、3 条件の反例を探す。成立の認定はさせず、反例の一覧だけを、止める反例か申し送りかを付けて返させる。止める反例には、食い違う相手の引用を添えさせる。保存の無いものだけ読み手が自分で引いて保存し、引いた回数を返させる
- 見た目の優劣と好みは読ませない。デザインは Figma が決めている
- 3 条件の外の指摘は、申し送りとして分けて返させる
- 自分の自己評価と作業の経緯は渡さない

止める反例は自分で見送らず、申し送りに移さない。直すのは止める反例だけで、申し送りは直さず残存課題に置く。直した後に何を読ませるか（同じ読み手に増分か、新しい目に全量か）は自分で決める。

## 不変条件

- `../_shared/references/figma-mcp.md` の「読み方の規則」に従う
- 補ったものは作業の記録の「補ったもの」に載せる
- `spec/design/pages/` を作らない
- `spec/pages/` と `spec/scenario/` を書き換えない
- 未完了を完了と報告しない

## 予算

次のいずれかに達したら止め、成り立っていない条件と、残っている止める反例・申し送りを分けてユーザーに渡す。

- 独立した読みの反例 → 修正 → 読み直し: 3 周まで
- 同じ作業の再委譲: 2 回まで（2 回目はスコープを分割する）

## ユーザーに聞く場面

次の場面だけ、まとめて一度に聞く。回答を待つ間は、答えに依存しない作業を進める。

- Figma の URL が無い
- 見積もった呼び出し回数がシートの上限を超える
- `spec/design/` に別の出どころの `tokens.md` がある（上書きしてよいか）
- Figma にある画面に `spec/design/pages/*.html` がある（HTML を消し、フレームを正本にしてよいか）
- 同じ画面を描いたフレームが複数のページにあり、どれを対応表に載せるか決まらない
- フレームと画面の対応が、フレーム名と `spec/pages/index.md` から決まらない
- フレームによって使っているテーマのモードが違い、どれを取り込むか決まらない

## 環境の事実

Figma MCP のツール・呼び出し回数・応答の保存は `../_shared/references/figma-mcp.md` に従う。このスキルでの決まりは次のとおり。

- `{figma-dir}` はプロジェクトルートの `.figma-import/` とする。セッションをまたいだ再開に使い、完了したら消す
- 対応表はフレーム名と幅から作る。フレーム名が画面・状態・ビューポートを表す（`{プロジェクト} / {画面} / {状態} / Desktop` など）ときは名前に従い、表さないときは幅と中身から決める
- 条件 2 の値は、`use_figma` のスクリプトで対応表のフレーム配下を走査して集める。値ごとに、プロパティ・出現したフレーム・Variables への結び付きを書き出す。フレームごとの `get_design_context` は、走査で読めない値を確かめるときだけ使う
- 呼び出し回数の見積もりには、`whoami`・`use_figma`（ページごとの一覧と走査）・`get_metadata`・`get_variable_defs` と、読み手が引く分を 3 周ぶん含める
- 1 日の上限に届いたら、対応表と走査の済んだページを残して止まる。翌日は「取り込み元」から再開する

## 完了報告

```text
figma-import: {完了 / 停止（理由）}
- 段取り: {採った進め方を一行で}
- 取り込み元: {Figma URL}
- 対応表: {数} 画面（デスクトップとモバイルの両方 {数}、片方だけ {数}、Figma に無い {数}）
- トークン: Variables {数}・スタイル {数}、Variables 外から足した値 {数}、寄せる規則で解決する値 {数}
- 補ったもの: {方針の項目と書体の一覧 / なし}
- 対応表に載せなかったフレーム: {spec/pages に無いフレーム / なし}
- Figma の呼び出し: {回数} 回（見積もり {回数} 回）
- 独立した読み: {回数と、各回の止める反例と申し送りの数。完了なら最後の回は止める反例ゼロ}
- 残存課題: {申し送りの数。spec/design/index.md の「取り込み元」 / なし}
```

報告の最後に次を添える。

- 画面の実装は `spec-implement` が対応表のフレームを読んで行う
- Figma に無い画面を実装の前に HTML で確かめたいときは、design-flow で画面を追加する
- Figma の Variables・スタイル・フレームの構成を変えたら、このスキルを再実行する
