# Figma Import

Figma のデザインを `spec/design/` に取り込む。取り込みはプロジェクトの立ち上げ時に一度だけ行い、以後の正本は `spec/design/` とする。Figma の更新は追わない。画面の追加は `../design-flow/SKILL.md` が、取り込んだトークンと方針に沿って行う。

段取り（フレームの読み方・委譲の切り方・確かめ方）は画面数と Figma の作りに合わせて自分で決める。このスキルが定めるのは、入力・成果物・完了の定義・独立した読み・不変条件・予算。

着手時に、読んだ Figma の規模感と採る段取りを一言宣言する。

## 入力

- Figma の URL。ファイル・ページ・フレームのどれでもよい
- `spec/pages/index.md`: 取り込む画面の一覧と、各画面の目的・機能。無ければ `../spec/SKILL.md` でページ設計を先に行うよう提案して止まる
- `spec/scenario/`: あれば、画面の用途を読むのに使う

`spec/design/index.md` の「取り込み元」が同じ Figma を指していれば、前回の続きとして再開する。成果物と完了の定義を照らし、成り立っていない条件から進める。

## 成果物

形式は design-flow と揃える。design-flow の Phase 3 以降と、`spec/design/` を読む他のスキル（spec-implement・issue-ship・spec-sync）がそのまま使える。

| ファイル | 形式 | 値の出どころ |
| --- | --- | --- |
| `spec/design/tokens.md` | `../design-flow/references/phase2-tokens.md` の Step 1 | Figma |
| `spec/design/index.md` | 同 Step 2 と、下の「取り込み元」 | Figma から読み取れる方針。読み取れない項目は補う |
| `spec/design/pages/{画面名}.html` | `../design-flow/references/phase3-production.md` の作成条件 | Figma のフレーム |
| `spec/design/assets/` | Figma から書き出した画像・アイコン | Figma |

- 形式と Figma の値が食い違うときは、値は Figma に従う。色は Figma の値を OKLCH に変換し、HEX を併記する。OKLCH は、HEX に戻したときに Figma の HEX と一致する桁まで残す
- CSS カスタムプロパティの名前は、`get_design_context` の参照コードが `var(--…)` に書く Variables の名前（`/` や空白を `-` にした形）をそのまま使う（`--ink`・`--space-48` など）。design-flow の命名例には合わせない。Variables の無い値だけ design-flow の命名規則で名付ける
- Variables にテーマのモード（Light / Dark など）があれば、フレームが使っているモードだけを取り込み、他のモードは `index.md` のスコープ外の項に書く
- 書体は Figma の書体を指定する。Web フォントとして読み込めない書体は、フォールバックを決めて「補ったもの」に載せる
- ブレークポイントは design-flow の標準値を使う
- `clamp()` などの流動的な値は、Figma のフレーム幅で読んだ値になるときだけ使う。design-flow の作成条件にある流動的タイポグラフィ・流動的レイアウトより、フレーム幅での一致（完了の定義 2）を優先する
- design-flow の「デザイン原則」（様式の選定）は適用しない。`index.md` のデザイン様式の項には、Figma から読み取れる様式を書く
- 同じ画面の状態は、画面本体の外に置いた `<nav data-design-states>` で `<body>` の `data-state` を切り替えて見せる。この切り替えがデザイン確認用で実装の対象ではないことを `index.md` に書く。ホバー・フォーカスなどのインタラクション状態は疑似クラスで書き、この切り替えに含めない

完了したら、「取り込み元」の状態を「完了」にし、`spec/index.md` に `spec/design/` の成果物を追記する。

### 取り込み元

`spec/design/index.md` に次を書く。着手時に Figma の URL と対応表を書き、画面を作るたびに更新する。止まった後の再開はここから始まる。

- 状態: 取り込み中 / 完了。着手時に「取り込み中」と書き、完了の定義が成り立つまで変えない。design-flow は「取り込み中」の間、画面を作らない
- Figma のファイル URL と取り込んだ日
- 正本は `spec/design/` で、Figma は更新しないこと
- 画面と Figma の対応表（画面名・デスクトップのフレーム・モバイルのフレーム・状態のフレームかバリアント）
- 補ったもの: Figma に無く、トークンと方針から作った画面・ビューポート・状態と、書体のフォールバック
- 寄せた値: スケール外の元の値と、寄せた先のトークン

## 完了の定義

次の 5 つが成り立ち、それぞれを根拠で示せること。成り立つとは反例が無いこと。

### 1. 画面が揃っている

- `spec/pages/index.md` の全画面に HTML が 1 つずつある
- デスクトップとモバイルのフレームがある画面は、1 つの HTML にまとまっている
- 同じ画面の状態を描いたフレーム（入力済み・エラー・メニューを開いた状態・絞り込み後など）は、別の画面にせず、その画面の HTML の中で切り替えて見られる
- Figma にあって `spec/pages/index.md` に無いフレームは作らず、完了報告に挙げる
- Figma に無い画面とビューポート（片方しかない画面の残り・タブレット幅）は、トークンと方針から作り、「補ったもの」に載っている

根拠: 対応表

### 2. Figma を正しく写している

- レイアウト（並びの向き・揃え・サイズの決まり方）は、そのフレームを `get_design_context` で読んだ値から来ている。Figma のフレーム幅で描画したとき、gap・padding・サイズ・色・文字・角丸・影・画像は読んだ値と一致する。色は HEX で照らす。「寄せた値」と「補ったもの」に載っている値だけは例外
- Figma のテキストノードの文言が、そのまま HTML にある
- デスクトップとモバイルの構造の違い（サイドバーとボトムナビ、テーブルとカード、モバイルで消える要素）は Figma のとおりで、どちらかに寄せていない
- Figma のフレーム幅で描画した HTML を Figma のスクリーンショットと並べ、要素の抜け・並びの違い・画像の欠けがない

根拠: 画面ごとの、読んだフレームの nodeId、フレーム幅での値の照合結果、文言の照合結果、フレーム幅での並べ比べの結果

### 3. トークンを使っている

トークンにする値（以下「トークンの対象」）は、色・フォントサイズ・行の高さ・字間・ウェイト・余白・角丸・影・線の太さ。幅と高さは対象にせず、Figma で読んだ値をそのまま書く。

- Figma で使われているトークンの対象の値は、「寄せた値」を除いてすべて `tokens.md` にあり、HTML は `:root` のトークンを参照する
- `:root` の外に、トークンの対象の値が直書きされていない（`0`・`100%`・`auto` などは除く）
- 繰り返し現れる値はトークンになっている。一度しか現れないスケール外の値は、トークンにするか、近いトークンに寄せて「寄せた値」に載っている。寄せてよいのは余白・角丸・フォントサイズで、寄せた先との差が 2px 以下のものだけ。色と影は寄せない
- ビューポートで変わる値（見出しのサイズ・余白）は `tokens.md` にある。Variables にビューポートのモード（Desktop / Mobile など）があれば、モードごとの値をそのまま使う。モードごとの値は `@media` の中の `:root` で上書きし、これは `:root` の外に当たらない

根拠: 直書きを探した検索の結果

### 4. レスポンシブになっている

- モバイルファーストで書かれ、デスクトップとモバイルを標準ブレークポイントのどこで切り替えるかが `index.md` のレスポンシブ戦略にある
- モバイル・タブレット・デスクトップ（375・768・1280）と、デスクトップとモバイルを切り替えるブレークポイントの前後（その幅と 1px 下）で、横スクロール・見切れ・重なり・届かない操作がない
- Figma のフレーム幅で、そのフレームと同じ構造になる。構造は、要素の有無と並びをフレームのノードの木と照らして判定する

根拠: 3 ビューポート、切り替えの前後、Figma のフレーム幅での観測

### 5. 状態が揃っている

- 主要なインタラクティブ要素に、design-flow の作成条件にあるインタラクション状態（ホバー・フォーカス・アクティブ・無効・エラー）がある
- Figma に描かれている状態（状態のフレームと、コンポーネントのバリアント）は Figma のとおり。無い状態はトークンから作り、「補ったもの」に載っている

根拠: 状態ごとの出どころ

## 独立した読み

完了と判断する前に、新しいコンテキストのサブエージェント 1 体に読ませる（委譲方式と待ち方は `../_shared/references/subagent-policy.md`）。

- Figma の URL、対応表、`spec/pages/index.md`、`spec/design/`、応答の保存先（下の「Figma MCP」）、agent-browser の namespace とセッション名、完了の定義の 5 条件（転記）を渡す
- 画像を読めなかったら判定せず、その旨を返して止まるよう伝える
- 読み手は保存済みの Figma の応答とスクリーンショットを HTML と照らし、5 条件の反例を探す。成立の認定はさせず、反例の一覧だけを返させる。保存の無いものだけ読み手が自分で引いて保存し、引いた回数を返させる
- 読み手の後片付けは自分のセッションの `close` だけにさせ、`close --all` は実行させない
- 見た目の優劣と好みは読ませない。デザインは Figma が決めている
- 5 条件の外の指摘は分けて返させる
- 自分の自己評価と作業の経緯は渡さない

5 条件への反例は自分で見送らない。直した後に何を読ませるか（同じ読み手に増分か、新しい目に全量か）は自分で決める。

## 不変条件

- Figma のファイルを書き換えない。`use_figma` で実行するのは読み取りだけのスクリプトに限る
- Figma のデザインを良くしようとしない。Figma と食い違う「改善」は、読み手が勧めても入れない
- Figma から読めない値を推測で埋めない。補ったものは記録する
- Figma との一致は、読んだ値との照合で示す。スクリーンショットが似ていることを一致の根拠にしない。スクリーンショットは、抜け・並び・画像の欠けといった反例を探すのと、崩れの確認に使う
- Figma MCP を使えないときは、スクリーンショットからの再現に切り替えず止まる
- `spec/pages/` と `spec/scenario/` を書き換えない
- 画像を読めないまま判定しない
- 未完了を完了と報告しない

## 予算

次のいずれかに達したら止め、成り立っていない条件と残りをユーザーに渡す。

- 独立した読みの反例 → 修正 → 読み直し: 3 周まで
- 同じ作業の再委譲: 2 回まで（2 回目はスコープを分割する）

## ユーザーに聞く場面

次の場面だけ、まとめて一度に聞く。回答を待つ間は、答えに依存しない画面を進める。

- Figma の URL が無い
- 見積もった呼び出し回数がシートの上限を超える
- `spec/design/` に別の出どころの `tokens.md` か `pages/*.html` がある（上書きしてよいか）
- 同じ画面を描いたフレームが複数のページにあり、どれを取り込むか決まらない
- フレームと画面の対応が、フレーム名と `spec/pages/index.md` から決まらない
- Figma と `spec/pages/index.md` で、画面に載せる情報・操作が食い違う
- フレームによって使っているテーマのモードが違い、どれを取り込むか決まらない

## 環境の事実

### Figma MCP

公式の Figma MCP を使う。`fileKey` と `nodeId` は URL から取る（`figma.com/design/{fileKey}/...?node-id=1-2` の nodeId は `1:2`）。

- `use_figma`: Plugin API のスクリプトを実行する。次の 4 つはこれで取る
  - ページの一覧（`figma.root.children`）と、ページ直下のフレームの id・名前・サイズ
  - ローカルの Variables の全定義（`figma.variables.getLocalVariableCollectionsAsync()`）。コレクション・モード・エイリアスを含む
  - テキストスタイルの一覧
  - コンポーネントセットとバリアントの一覧。ホバー・フォーカス・無効などの状態は、フレームではなくバリアントで描かれていることが多い
- `use_figma` を呼ぶ前に、公式プラグインの `/figma-use` を読み込む。1 回のスクリプトで切り替えるページは 1 つまでとし、複数のページは並列の呼び出しに分ける
- `get_metadata`: ノードの id・名前・サイズの木を返す。`nodeId` を省いて返るページの一覧は全ページを含まないので、ページの一覧には使わない
- 対応表はフレーム名と幅から作る。フレーム名が画面・状態・ビューポートを表す（`{プロジェクト} / {画面} / {状態} / Desktop` など）ときは名前に従い、表さないときは幅と中身から決める
- `get_design_context`: フレームの React + Tailwind の参照コード、使われているテキストスタイル、スクリーンショットを返す。値は `var(--{Variables 名}, {値})` の形で入る
  - 大きいフレームは中身の薄い応答になるので、子ノードを引き直す
  - 呼ぶ前に、公式プラグインの `/figma-design-to-code` を読み込む（プラグインが必須にしている）。プラグインの指示は次のように読み替える
    - スクリーンショットを見た目の目標にする指示は、完了の定義 2 のフレーム幅での並べ比べで満たす。一致の根拠は値の照合とする（不変条件）
    - プロジェクトのスタックに合わせる指示のスタックは、design-flow の作成条件どおりの素の HTML と CSS。参照コードはこれに書き換える
    - プロジェクトのコンポーネントを再利用する指示は、`spec/design/` が単体の HTML なので当てはまらない
- `get_screenshot`: ノードの PNG の URL を返す（URL は短時間で切れる）。並べ比べに使うフレーム全体のスクリーンショットはこれで取る。`maxDimension` をフレームの長辺以上にして等倍で取り、すぐに保存する
- `get_variable_defs`: そのノードの配下で使われている Variables とテキストスタイルを、解決済みの値で返す。ローカルに定義の無い値（ライブラリから使っている Variables など）を補うのに使う
- テキストスタイルの `letterSpacing` は % で返り、参照コードは px で書かれる
- 画像とアイコン: `get_design_context` の応答にある URL は 7 日で切れる。その場で `spec/design/assets/` に保存し、HTML からは `../assets/` で参照する。応答に無い画像は `download_assets` で取る

呼び出し回数には上限がある。Professional 以上のプランの Full / Dev シートは 1 日 200〜600 回・1 分 10〜20 回、View / Collab シートは月 6 回まで。

- 着手時に `whoami` でプランとシートを確かめ、必要な回数を見積もる。`whoami` は上限の数を返さない。プランから上限が決まらないときは、範囲の下限（1 日 200 回・1 分 10 回）を上限とみなす。回数は Figma MCP の全呼び出しの合計で、`whoami`・`get_metadata`・`use_figma`、フレームごとの `get_design_context`（子ノードの引き直しを含む）・`get_screenshot`、`get_variable_defs`・`download_assets` と、読み手が引く分を 3 周ぶん含める
- 1 分に投げる呼び出しは、1 分の上限の半分までにする。並列で委譲するときは、委譲先ごとに 1 分に使ってよい回数を割り当てて渡し、合計を半分に収める
- 応答はプロジェクトルートの `.figma-import/` に保存し、同じ呼び出しを 2 度しない。保存するのは呼び出した本人
  - ノードへの呼び出しは `{nodeId}.md`（nodeId の `:` は `-` にする）に、ツールごとの節に分けて参照コード・テキストスタイル・Variables の値を書き出す
  - フレームのスクリーンショットは `{nodeId}.png`
  - `use_figma` の結果は、取ったものの名前で置く（`pages.md`・`variables.md`・`text-styles.md`・`components.md`）
  - `.figma-import/` は `git rev-parse --git-path info/exclude` が示すファイルに足してコミットに入れず、セッションをまたいだ再開に使い、完了したら消す
- 1 日の上限に届いたら、HTML を作り終えた画面を残して止まる。翌日は「取り込み元」の対応表から再開する

### ブラウザ観測

`agent-browser` で `file://` の HTML を開き、`set viewport {幅} {高さ}` と `screenshot` で観測する（`../_shared/references/agent-browser.md`）。Figma のフレーム幅での観測は、ビューポートをフレームの幅と高さにして、`screenshot --full` でページ全体を撮る。着手時に `agent-browser session id --scope worktree --prefix figma-import` でこの実行の namespace を決め、全コマンドに付ける。作業全体の開始前と終了時に `agent-browser --namespace {ns} close --all` を 1 回ずつ実行する。ブラウザのスクリーンショットは `{scratchpad}`（`../_shared/references/scratchpad.md`）に置き、リポジトリに残さない。
