# 画面の見た目

`spec/design/` があるときの、画面の見た目の項目・完了条件・照合の方法。

## 正本

画面ごとの見た目の正本は次のとおり。上の行ほど優先する。

| 画面 | 正本 |
| --- | --- |
| `spec/design/index.md` の「取り込み元」の対応表にフレームがある | そのフレーム |
| `spec/design/pages/{画面名}.html` がある | その HTML |
| どちらも無い | `spec/design/tokens.md`、`spec/design/index.md` の方針、実装済みの同種の画面 |

- 対応表に「Figma に無い」とあるビューポートと、正本に描かれていない状態は、`index.md` の `## 補う規則` に従って作る。この節が無いプロジェクトでは、`index.md` の方針と同種の画面に合わせる
- 画面に載せる情報・操作が正本と `spec/pages/` で食い違うときは、`spec/pages/` に従う。食い違いは実装報告に書く
- 「取り込み元」があって「正本の分担」が無いときは、画面の HTML まで作っていた形式の取り込みで、対応表に nodeId と「補う規則」が無い。Manager は画面の見た目の項目を委譲する前に、`/figma-import` の再実行をユーザーに求める。回答を待つ間は、見た目以外の項目を進める

## 項目

`spec/pages/` の画面ごとに「{画面名} の見た目」の項目を一つ置く。振る舞いの項目と同じフェーズで実装してよいが、合否は分けて出す。

## 完了条件

### すべての画面

- トークンの対象（色・フォントサイズ・行の高さ・字間・ウェイト・余白・角丸・影・線の太さ）は `tokens.md` のトークンを参照する。トークンに無い値は「補う規則」があれば従う。規則が無いか、規則で解決できない値は、Implementer が Manager に報告し、Manager が `tokens.md` に足すか規則を直す
- 375・768・1280 と、`index.md` のデスクトップとモバイルの切り替え幅の前後（その幅と 1px 下）で、横スクロール・見切れ・重なり・届かない操作がない
- 主要なインタラクティブ要素に、ホバー・フォーカス・アクティブ・無効・エラーの状態がある
- 共通要素（ヘッダー・ナビゲーションなど）は、実装済みの画面と同じ部品を使う

### フレームが正本の画面

- レイアウト（並びの向き・揃え・サイズの決まり方）と、gap・padding・サイズ・色・文字・角丸・影・画像は、フレーム幅で描画した画面の実測が `get_design_context` で読んだ値と一致する。色は HEX で照らす。「補う規則」で寄せた値は、寄せた先との差が規則の範囲にある
- 固定の文言（見出し・ラベル・ボタン・空状態の文）は Figma のテキストのとおり。データで変わる箇所は、Figma の例と同じ書式で表示する
- デスクトップとモバイルの構造の違い（サイドバーとボトムナビ、テーブルとカード、モバイルで消える要素）は Figma のとおりで、どちらかに寄せていない
- Figma に描かれた状態（状態のフレームと、コンポーネントのバリアント）は Figma のとおり
- Figma の例に近いデータを入れ、フレーム幅で撮った画面を Figma のスクリーンショットと並べて、要素の抜け・並びの違い・画像の欠けがない

### HTML が正本の画面

フレームの条件を、HTML を同じ幅で描画して測った値と文言に読み替える。並べ比べは 375 と 1280 で行う。

### 方針が正本の画面

「すべての画面」の条件に加え、置き方・言い回しが同種の画面と揃っている。

## 根拠

フレームか HTML が正本の画面:

- 正本の参照先（フレームの nodeId か HTML のパス）
- 値の照合結果: プロパティごとに、正本の値と画面の実測
- 文言の照合結果
- 並べ比べに使ったスクリーンショットの参照先と、見つけた違い
- 崩れを確かめた幅と結果

方針が正本の画面:

- トークンを参照していることを確かめた結果（直書きを探した検索の結果）
- 崩れを確かめた幅と結果
- 比べた同種の画面と、使った共通の部品

根拠の無い項目は受け入れない。スクリーンショットが似ていることを一致の根拠にしない。

## 担当

- Implementer は正本を読んで実装し、上の根拠を添えて完了候補を報告する
- Verifier は Implementer の照合を引き写さず、自分で画面を描画して測り、正本の値と照らす。保存済みの Figma の応答は Figma の値そのものなので、そのまま使ってよい。Verifier が Figma から引いたものは `{figma-dir}` にだけ保存し、プロジェクトのファイルは変えない
- 見た目の優劣と好みは判定しない。デザインは正本が決めている

## Figma の読み方

`../../_shared/references/figma-mcp.md` に従う。このスキルでの決まりは次のとおり。

- `{figma-dir}` は `{run-directory}/figma/` とする。Implementer と Verifier が共有する
- `get_design_context` の参照コードは、プロジェクトのスタックに書き換え、プロジェクトのコンポーネントを再利用する
- 画像とアイコンは、Implementer が応答を受け取ったその場で、プロジェクトの静的ファイルの置き場所に保存する
- 開始時に Manager が、Implementer と Verifier から Figma MCP を呼べるかを確かめる。呼べなければ、フレームが正本の項目を `blocked` にしてユーザーに伝える
- Manager は開始時に呼び出し回数を見積もって `plan.md` に記録し、委譲のたびに 1 分あたりの割り当てを渡す。1 日の上限に届いたら、Figma を読む項目を `blocked` にして翌日を再開条件に書き、Figma を読まない項目を進める
- フレーム幅での観測は、ビューポートをフレームの幅と高さにして、ページ全体を撮る
