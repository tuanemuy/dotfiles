ドキュメントは、対象の現在の姿を述べる。書き手と過去は登場しない。

読者が知りたいのは「今どうなっているか」「何をすればよいか」であって、そこに至った道のりや書き手の気持ちではない。文ごとに「この文の主語は対象か、それとも書き手や過去か」を問い、後者なら削る。この一つの問いで、経緯・弁明・言い直し・ぼかしはすべて落ちる。

- 経緯（「当初は〜だったが」「議論の結果〜になった」）は過去を語っている。今の状態だけを書く。
- 弁明（「本来は〜すべきだが」「暫定的に」「〜で申し訳ないが」）は書き手を語っている。決めたことを書く。
- 言い直し（「つまり」「言い換えると」、規則をなぞるだけの例）は書き手が二度言っている。よい方を一つ残す。
- ぼかし（「基本的に」「原則として」「〜かもしれない」「〜が望ましい」）は書き手の迷いを語っている。「する」「しない」で書く。

## 残るもの

削るのは言葉であって、事実ではない。

- 理由は、今も成り立つ制約なら残る。「Bがサポートされないため、Aが必要」は対象の現在を述べている。「Bが遅かったのでAを入れた」は過去を述べている。今も成り立つなら「Bが遅いため、Aを使う」と現在形に書き直す。成り立たないならユーザーに確認する。
- 未決は、未決という現在の事実として書く。「〜かもしれない」ではなく「未決」と書く。断定にするために決まっていないことを決めない。
- 例外は、条件を列挙した断定文にする。「原則として」で逃げない。

経緯を消すと論理がつながらなくなる箇所では、経緯が現在の事実を隠し持っている。その事実を現在形で書き足す。書き足せないなら、推測で補わずユーザーに確認する。

## 文章

文の単位では [明快な文](../_shared/references/clear-writing.md) に従う。語調は既存のドキュメントに合わせ、新規なら常体で書く。

悪い例:

```markdown
当初は Redis を検討していましたが、運用負荷の観点から議論した結果、現時点では暫定的に SQLite を使うこととしています。つまり、基本的には SQLite で問題ないはずですが、将来的に見直す可能性があります。
```

良い例:

```markdown
運用対象を増やさないため、ストレージは SQLite を使う。Redis への移行は未決。
```

## 進め方

1. 対象を決める。引数 `target` があればその対象、なければ git diff の変更分や会話中で扱っているドキュメントを対象にする。
2. 文ごとに主語を問い、書き手と過去を削る。削った結果つながらない箇所は、現在の事実を書き足す。
3. 明快な文に従って残った文を整える。
4. 削る前と後で、対象について述べている現在の事実が減っていないこと、変わっていないことを確かめる。
5. 記法の整形が必要なら markdown-style に渡す。

事実が決められない、あるいは削ると意味が変わる箇所は、ユーザーに確認する。
