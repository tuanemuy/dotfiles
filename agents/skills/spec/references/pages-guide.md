# ページの形式

すべてのシナリオを実現する画面の構成を述べる。上流・下限・上限は `../../_shared/references/spec-ready.md` の層の表が定める。

出力先: `spec/pages/index.md`

各画面について以下を記載する:

- **画面名**
- **目的**: この画面が存在する理由
- **機能**: この画面で行えること（箇条書き）
- **状態**: 画面が取りうる状態（読み込み中・空・エラー・成功等）と遷移のきっかけ

ページが答えるのは、シナリオを実現する画面が揃っていて、各画面が何をするかまで。個々の挙動の精密化は domains 以降の層が担う。次は書かない。

- 条件の組み合わせ（入力値 × 状態 × リソースの有無など）を展開した個別ケースの挙動。既に書かれた原則・共通規則から導出できるものは、規則がある時点で定義済み
- 状態遷移の詳細な事前条件・事後条件、データ項目の型・制約・保持規則
- エラーメッセージの文面や表示内容の細目
