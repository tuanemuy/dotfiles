# シナリオの形式

利用者の視点から、システムが提供する操作とそのフローを述べる。上流・下限・上限は `../../_shared/references/spec-ready.md` の層の表が定める。

## シナリオ一覧

出力先: `spec/scenario/index.md`

- システムが提供する操作を利用者視点で列挙する
- 条件分岐とエラー処理は含めない
- 必要に応じてカテゴリーに分ける

## シナリオ詳細

出力先: `spec/scenario/${category}.md`（カテゴリーごとにファイルを分ける）

- 利用者の視点で、具体的なフローが分かるように書く
- 正常系に加え、契約が定める異常系と、4 観点（入力エラー・権限不足・リソース不在・操作の取り消し）の異常系を書く
- UI パターン（タブ・モーダル等）は書かない。画面構成は pages が決める

カテゴリーは互いに独立している。カテゴリー単位で並列に委譲するときは、委譲先に契約と `spec/scenario/index.md` を読ませる。
